# CrowdSec integration

This repository provides an optional CrowdSec integration for Nginx running directly on the Fedora Server host. CrowdSec reads host Nginx access logs and evaluates them with the `crowdsecurity/nginx` collection.

The integration starts in detection-only mode. It does not install a remediation component or bouncer, configure OPNsense, change router rules, or enable automatic IP blocking. Independently installed bouncers remain untouched and may continue enforcing their own decisions.

## Requirements

- Fedora Server with the repository-managed host Nginx service
- Root access
- Working Nginx configuration
- `curl`, `dnf`, `flock`, `awk`, `sha256sum`, `runuser`, and `usermod`

## Enable and manage

Run `sudo ./install.sh` and choose **9) Manage CrowdSec**. During the Nginx stage, a one-time optional offer is also shown unless CrowdSec was previously declined or configured.

The management menu can install or configure CrowdSec, refresh Nginx log discovery, show status and metrics, or remove only this repository integration.

## What the integration changes

The Fedora Server and Proxmox Nginx templates explicitly write `combined` access logs. Managed application virtual hosts use the access logs generated by the repository application helper.

The integration reads `nginx -T`, extracts absolute `access_log` destinations, converts Nginx variables to glob patterns, and writes `/etc/crowdsec/acquis.d/fedora-server-nginx.yaml`. It ignores `off`, syslog, relative paths, and non-path destinations.

A systemd timer checks for Nginx log configuration changes every five minutes. Unchanged acquisition configuration does not restart CrowdSec. A lock prevents concurrent manual and timer refreshes. The timer uses a managed runtime copy under `/opt/fedora-server-setup/`.

The updater refreshes the installed CrowdSec runtime files only when their recorded ownership hashes still match. Locally modified runtime files are not overwritten.
The log-target state file is also protected by ownership metadata. Files with unknown ownership, modified content, or symbolic-link paths are not overwritten or removed. Runtime synchronization stages both files and restores the previous pair if replacement or state persistence fails.

## Log permissions and rotation

The integration adds the `crowdsec` service account to the `nginx` group when that group exists. It does not make logs world-readable or rewrite the system logrotate policy. Existing and newly rotated log files must remain readable by the `nginx` group.

After enabling the integration, verify the active and rotated log files:

```bash
sudo id crowdsec
sudo namei -l /var/log/nginx/access.log
sudo ls -l /var/log/nginx/
sudo runuser -u crowdsec -- test -r /var/log/nginx/access.log
```

If your Nginx logrotate configuration creates files without group read access, adjust its `create` mode and group according to the local Nginx package configuration. Recheck after a real rotation. Do not use `chmod 777`, disable SELinux, or trust arbitrary forwarded client headers.

SELinux denials can be inspected with:

```bash
sudo ausearch -m AVC -ts recent | grep -Ei 'crowdsec|nginx'
```

## Client IP address

CrowdSec decisions depend on the client IP recorded in Nginx access logs. Check the `remote_addr` field in generated log entries and compare it with the address of a test client.

If an HTTP reverse proxy sits in front of Nginx, configure Nginx real-IP handling only for explicitly known proxy addresses or CIDRs. This integration does not change real-IP or proxy trust settings.

## Install and supply-chain behavior

If CrowdSec is not installed, the module downloads the official bootstrap script over HTTPS, displays its SHA-256 digest, and asks for explicit approval before executing it as root. The digest is informational and is not an independently authenticated vendor checksum. Fedora package signature verification remains enabled.

If CrowdSec is already installed, the module reuses it and installs the Nginx collection only when absent. It does not uninstall CrowdSec packages, databases, credentials, collections, or independent bouncers.

## Verification

```bash
sudo nginx -t
sudo crowdsec -t
sudo cscli collections list
sudo cscli metrics
sudo systemctl status crowdsec
sudo systemctl status fedora-server-crowdsec-refresh.timer
sudo journalctl -u crowdsec --since today
```

Confirm that `cscli metrics` shows log lines being read and parsed. Check logrotate and SELinux if files are not consumed.

## Removal and retained data

Choose **4) Remove this repository integration** in the CrowdSec menu. Removal deletes only files whose content still matches the recorded integration-owned hash. Modified or unowned files are retained, and the ownership state is kept when any managed file remains. CrowdSec packages, databases, credentials, collections, independent bouncers, and unrelated configuration are retained.

The complete managed server package removal stops if CrowdSec integration cleanup fails, so the operator can review the remaining files before continuing.

## Validation

Run:

```bash
bash -n scripts/crowdsec.sh
bash tests/test-crowdsec-discovery.sh
git diff --check
```

A Fedora test VM is still required before production use. Static tests do not validate package installation, systemd behavior, SELinux policy, logrotate behavior, or real log ingestion.
